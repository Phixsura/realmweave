# Weave & Sever v2 — 详细设计

状态：**设计稿，待真人对局验收**。实现前必须由设计负责人（用户）逐节确认。
本文档是唯一权威；实现与本文冲突时以本文为准。

---

## 0. 设计目标与非目标

**目标**
1. 攻防同一：阻碍对手的手同时必须推进自己的胜利。
2. 深度来自 Realmweave 原生资产：三界、门柱、起源、编织、冗余。
3. 规则 5 分钟可学，全文不超过一页。
4. 无平局倾向（classic 的问题）也无必然平局（doubleweave 的问题）。

**非目标**
- 不追求围棋式手数（价值密度 > 手数）。目标 40–120 手/局。
- 不引入：气、提子、数目、贴目。先手优势用已有的 pie rule。
- 本版不做非对称三界（留给 v3 实验）。

## 1. 规则全文（玩家可见版本）

> 双方轮流行动。你的一手棋，三选一：
>
> **落子** —— 在任意空节点放一颗棋子。棋子永不移动、永不消失。
>
> **剪线** —— 永久移除棋盘上的一条线（含门柱线）。任何人都不能再经过。
> 每人整局共 **3 把剪刀**。与起源直接相连的线不可剪。
>
> **停一手** —— 什么都不做（罕用，见终局）。
>
> **编织胜利**：当你的三个起源通过你的棋子沿幸存的线连成一片，你完成
> "临时编织"。对手获得一整手回应（剪断你的桥，或完成他自己的编织）。
> 若你的编织在你下一手开始时仍然成立——你赢。
>
> **绞杀胜利**：任何时刻，若对手的三个起源在剩余的棋盘上**再也不可能**
> 连通（就算把所有空点都给他也连不上），你立即获胜。
> 你不得使自己陷入这种状态（此类剪线为非法手）。
>
> **终局回退**：若双方连续停一手，或棋盘已满且无人成网——比较双方
> "把所有剩余空点都给自己时的连通起源数"，多者胜；再平则比剪刀余量，
> 多者胜；仍平为和局。

## 2. 精确定义（实现者版本）

### 2.1 招法

```
Move::Place(NodeId)      // 已有
Move::CutEdge(EdgeId)    // 新增。EdgeId = 边在 BoardDefinition.edges 中的稳定索引
Move::Pass               // 已有
Move::Swap / Resign      // 已有（pie rule 照旧：Dark 第一回应可换边）
```

`GameState` 新增：
```
cut_edges:   BitVec / HashSet<EdgeId>   // 已被剪除的边
scissors:    [u8; 2]                    // 剩余剪刀 [Light, Dark]
```
图查询层（`BoardGraph::neighbors`）在此规则下必须经过 cut 过滤——引入
`LiveGraph<'a> { board, cut_edges }` 视图，所有连通性计算走它，不改动
底层 `BoardGraph`（其他规则零影响）。

### 2.2 合法性

`CutEdge(e)` 合法当且仅当：
1. 己方剪刀 > 0；
2. e 未被剪过；
3. e 的两端都不是**任何**起源（双方起源相邻边都受保护，见 §3.1）;
4. 剪后不造成**自我绞杀**（见 2.3 的可行性定义，对自己检查）。

`Place(n)`：空节点即可（与 classic 相同，无自杀概念——棋子不会死）。

### 2.3 绞杀判定（feasibility check）

定义 **potential-connectivity(P)**：在幸存图上，把 P 的所有棋子和所有
空节点视为可通行（对手棋子不可通行），P 的三个起源是否属于同一连通分量。

- 这是一次 BFS，O(V+E)，每手棋后对双方各算一次。
- **绞杀胜**：一手棋（落子或剪线均可触发！落子堵住最后通路同样成立）
  结算后，若对手 potential-connectivity = false → 行棋方立即获胜，
  优先级高于编织确认（先判死，再判活）。
- **自我绞杀非法**：若该手使自己 potential-connectivity = false → 拒绝。
  （对手的落子可以使你陷入绞杀——那是他赢了；只有"自己动手"被禁止。）

### 2.4 编织确认（与 classic 相同框架，但确认回合有真实牙齿）

- 完成编织 → `pending_weave = Some(me)`。
- 对手的回应手可以：(a) 剪断编织中的桥边使其破碎；(b) 完成自己的编织
  （则轮到"更早的临时编织"先确认——保持 classic 的先到先确认语义）；
  (c) 其他任意手（等于放弃抵抗）。
- 我下一手开始时编织仍成立 → 确认获胜。
- 编织破碎后 pending 清空，游戏继续（我可以修复——如果我还有冗余路径
  或空点可补）。

### 2.5 终局回退（防呆分支，正常对局极少到达）

连续两个 Pass，或无合法 Place 且双方剪刀为 0：
1. 比 potential-connected 起源的最大数目（3 > 2 > 1）；
2. 平则比剩余剪刀数；
3. 再平 → Draw。
此分支存在仅为保证游戏必然终止；平衡性不依赖它。

## 3. 关键参数与其依据（已跑图论验证）

### 3.1 起源邻边保护 —— 必要，数据支持

引擎实测（max-flow 边连通度）：

| 局面 | 起源对之间最小边割 |
|---|---|
| 无保护 | **3** —— 起源都在角上、度数 3，三剪刀直接处决一个起源，游戏退化为"谁先手谁剪死对方"，秒杀 |
| **保护起源邻边（采用）** | **8** —— 纯剪刀绞杀在空盘上不可能（K=3 < 8），绞杀必须"棋子筑墙 + 剪刀补刀"协同 |

这正是想要的经济学：**剪刀是手术刀，不是处决器**。绞杀是一整局压迫的
终点，不是三手棋的戏法。

### 3.2 剪刀数 K = 3 —— 初值，唯一待调核心参数

约束区间：
- K=0 退化为 classic（已证不行）；
- K ≥ 8 空盘纯剪绞杀成立（已证阈值），必须 K < 8；
- 每人 3 把 → 全场最多 6 剪，对比全图 294 条边（hex37）足够稀缺，
  每一剪都是事件。
- **调参协议**：真人对局若感觉"剪刀不敢用/存到烂"→ 试 K=4；
  "满场焦土"→ K=2。每个 K 值至少 3 局真人局再下结论。

### 3.3 门柱经济

- hex37/61/91 的层间门边各 12 条（H–M 12 + M–U 12 = 24 条门边）。
- 编织必须至少各穿一次 H–M 与 M–U。剪一条门边 = 移除 1/12 的界间容量，
  且门边在起源保护之外（除非恰与起源相邻——生成器保证起源不在门柱上，
  已由 board validator 强制）。
- 预期涌现战略：**夺门（在门柱两端落子护住）→ threats to cut →
  声东击西（佯攻此门实剪彼门）**。无需任何附加规则。

### 3.4 冗余经济（redundancy 回归核心）

- 一条独木桥编织 = 1 剪即碎。对手确认回合必剪 → 独木桥编织**从不成立**
  （对手剪刀 > 0 时）。
- 玩家的真实决策：织 2-边-不相交网（成本高、免疫单剪）还是赌对手剪刀
  已尽（数剪刀 = 数牌）。**对手剪刀余量成为全局最重要的公开信息**——
  UI 必须时刻显示（见 §5）。

## 4. 边界情形清单（实现测试的验收表）

| # | 情形 | 裁定 |
|---|---|---|
| 1 | 剪一条两端均空的边 | 合法（预防性拆桥是战略） |
| 2 | 剪对手棋子间的边 | 合法（这是主用途） |
| 3 | 剪自己棋子间的边 | 合法但需过自我绞杀检查（负向操作，一般是坏棋，不禁止） |
| 4 | 同一手同时触发"我绞杀你"+"我完成编织" | 绞杀先判——立即胜，无需确认回合 |
| 5 | 我的落子恰好使自己 potential-conn = false | 不可能——落子只增加自己的可通行集 |
| 6 | 对手确认回合剪桥，但我有第二条路 | 编织仍成立 → 我下手开始即确认胜（冗余的回报） |
| 7 | 双方同时 pending（我织完，他回应时织完他的） | 我先到先确认：他织完不阻止我的确认。他唯一自救是破坏我的网 |
| 8 | 剪刀均尽 + 盘面成死锁 | 走 §2.5 回退 |
| 9 | pie rule swap 后剪刀余量 | 随座位交换（剪刀属于座位不属于颜色执者——同 classic 的时钟语义） |
| 10 | 回放/序列化 | CutEdge 进 move_log；确定性重放必须复现 cut_edges 集合（新增 proptest） |

## 5. UI / 客户端设计

### 5.1 剪线交互
- HUD 常驻新按钮组：`落子模式 / 剪线模式`（快捷键 Tab 切换）。
- 剪线模式下：悬停一条边 → 边高亮为红色虚线 + 显示剪刀图标；点击确认。
  3D 视图中边是 gizmo 线，需要为边加不可见碰撞体（胶囊体）；
  2D 分析视图同理（此视图剪线操作更精准，预期玩家剪线时切 2D）。
- 被剪的边：**不渲染**（不是画成灰色——世界被改变了，就该看起来
  像被改变了），原位置留一个短暂的断裂粒子/淡出动画（MVP：直接消失）。

### 5.2 信息呈现（本规则的胜负手信息）
- **双方剪刀余量**：HUD 顶栏大号常驻 `✂ 你 3 | 对手 2`。
- **脆弱性警告**：己方 pending/潜在编织若存在"单边割点"（割一条边即断），
  该边以黄色脉冲提示自己（只提示自己，不提示对手——信息对称性靠
  玩家自己算，这是棋力的一部分；但 MVP 阶段先双方都显示，降低学习门槛，
  竞技模式再关）。
- **绞杀风险条**：每方起源 potential-connectivity 所依赖的最小割边数
  （1~8+），显示为 "生命线 ×N"。N=1 时红色警报。
- 讲解/回放系统（annotate）新增 CutEdge 文案：剪掉了什么、是否破坏编织、
  双方生命线变化。

### 5.3 协议 / 服务器
- `ClientMessage::CutEdge { edge: u32 }`；`MoveEvent.mv` 已是 `Move` 枚举，
  序列化自动覆盖。协议版本 bump 到 2（新增枚举变体对旧客户端不兼容）。
- 服务器侧无新授权逻辑——一切合法性仍由 `RuleSet::validate_move` 单点裁决。

§4 清单，然后由用户裁决手感 → 决定调 K / 改规则 / 进入下一轮。

## 8. 与既有六套规则的关系

- classic/sever/doubleweave/territory/supply/supply-range **全部保留**为
  历史实验（RuleSet 注册表照旧），文档标注各自结论。
- `weave-sever-v2` 若通过真人验收 → 成为新默认，classic 保留为教学模式，
  supply 系保留为"围棋味"变体模式。
- 本轮吸取的教训（见项目记忆 design-drift-lesson）：不再以 bot 模拟指标
  作为手感证据；每轮规则变更以真人对局为唯一验收。
